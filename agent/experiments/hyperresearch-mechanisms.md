# Hyperresearch 机制借鉴：实验基线

独立分支：experiment/hyperresearch-mechanisms，起点 main@329c95b7。本分支没有安装/复制 Hyperresearch 的完整产品和源码；借鉴其公开 MIT 项目的机制思想。真实效果必须单独测量。

机制与实现：
1. 任务原子化与覆盖矩阵：保留原始问题，补充分句后的不可删除要求，按ID跟踪覆盖。
2. 正式成稿前的 corpus critic：查看已回读和登记的证据，缺口有预算时允许一次定向补证。
3. 对抗式审查：沿用原来的语义 LLM 审核，再附加独立的指令覆盖、分析块和“全量证明”检查。
4. Patch 不整篇重写：后续提交保留前次批准的有证据块，随后重新进入语义审核。
5. 运行工作区：本地 JSON 记录阶段和统计，不包含原始提问、政策正文、答案或模型凭据。

启动：在 agent/.env 配置 QA_ENGINE=hyper。对照组用 QA_ENGINE=sdk 或 QA_ENGINE=controlled。前端仍调用现有 /api/runs；/api/research/prepare 的全部政策保护守卫仍存在，不能把能跑的 Agent 实验误认为 Web 准备链全部可用。

对照题：全量枚举舆论政策、跨地区政策比较、政策目标与既成事实区分。固定真实模型、发布库版本、有效配置与180秒预算，记录对象/维度覆盖、专家判定的结论正确性、引用准确、耗时、模型与工具调用、结果是否完整。实验版本可能更慢；也可能因审查更严格，partial 率升高。

工作区仅记录经脱敏的可观察指标，不支持崩溃后原地恢复，不能称为完整持久研究记忆。没有真实校园 Qwen+RAG 时只能验证机制与工程测试，不能宣称研究效果提高。
