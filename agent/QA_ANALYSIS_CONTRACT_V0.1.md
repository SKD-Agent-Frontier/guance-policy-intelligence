# QA 研究分析契约 v0.1

## 1. 目的与边界

将政策研究输出分为「可追溯政策事实」与「根据事实做出的分析判断」两层。前者遵循已有 Claim → EvidenceRef → 原文引句与数字核验；后者只绑定事实，不冒充政策原文。逻辑上可以进行归纳、比较、条件化解释，但**程序只验证证据依赖，不保证推论的语义正确性**。

本次只接入普通 QA 的 AgentOutput → RunResult → Web 结果链路，不添加模型调用、不修改 RAG/Compare/Organize/任务路由。

## 2. 模型输出（可选）

```json
{
  "answer": "两份政策分别提供了不同的支持措施。",
  "claims": [
    {"text":"政策甲提出产业园区建设。","chunk_ids":["source-a"],"quotes":["建设产业园区"]},
    {"text":"政策乙提出企业数字化改造支持。","chunk_ids":["source-b"],"quotes":["支持企业数字化改造"]}
  ],
  "analyses": [
    {
      "kind": "comparison",
      "text": "本轮两条政策措施在直接作用对象上存在差异：前者面向产业载体，后者面向企业改造。",
      "scope_note": "仅限本轮检索并读到的两条政策措施，未评估实施效果。",
      "supporting_claim_indexes": [0, 1]
    }
  ],
  "insufficient": false
}
```

注意：这里的文字及 source ID **仅演示结构**，不代表实际政策事实。

旧输出缺少 `analyses` 时按空数组处理；只有确实要求分析、且能引用至少两条不同事实时才生成分析。

## 3. 核验与失效策略

1. `analyses` 在 AgentOutput 中使用显式 Pydantic 字段；原始分析草稿不写入序列化 RunResult。
2. 每条分析必须带种类 `synthesis/comparison/implication`、正文、范围说明以及至少两条不同的 0 起点事实索引。
3. 分析依赖最初的事实文本和证据 ID 签名，不依赖过滤后重新排序的整数索引。任一事实因引用、数字、关键词或其他规则被删除/修改，其依赖分析直接失效，**不允许自动换绑其他 Claim**。
4. 只有在原文逐字核验成功、所有依赖事实及原文引用仍存在时才发布；缺失、超时、引用不可检验均不发布。
5. 接收的分析最多 3 条；输出在 `structured.schema_version = qa-analysis/1`，字段含 `supporting_claim_indexes`、`supporting_chunk_ids`、`verification = evidence_linked_only`。
6. 提出分析草稿的轮次会重建事实型 `answer`，以免已撤回分析继续出现在模型生成正文中。用户仍可查看事实与逐条原文。
7. 若无法发布，**不推断政策不存在，也不自动补写分析**。

## 4. 表示层

QA 在原有「研究结论」与「依据与引句」之间新增可选「研究分析」区块。分析条目始终带范围说明、支持事实和可点击原文。明确标示：「分析是基于政策事实的推理，不是政策原文，也不代表推理已获语义验证。」

## 5. 尚未解决的问题

- 关联正确不等于分析必然成立。后续需要语义蕴含、反证查找、矛盾检查与人工评测。
- 不做全库覆盖推断。按本轮证据限定范围，不能从未检索到推断不存在。
- 不实现动态研究计划、跨功能任务编排或长周期持续研究。
- 真实校内 Qwen + RAG 的研究质量、延迟与引用质量仍须做端到端验收。

## 6. 最小真实验收案例

输入：「分析十四五数字经济产业政策的主要施策方向和不同政策之间的异同。」

核对：输出包含真实可查的 `claims`；`analyses` 只连接已经采信的两条及以上事实；原文按钮能进入相应文献；人为撤回任一依赖证据后分析不再出现；若模型未形成有效推理，只展示事实而不伪造分析。

对照任务：「找出数字经济相关政策文件」。该任务不应额外生成未请求的综合分析。
