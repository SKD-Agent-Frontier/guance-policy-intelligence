# 一、研究结论交付规范

本文件记录研究答案的输入、输出和校验契约。运行时不读取本文件；实际规则以代码为准。

## （一）输入契约

- question：研究问题原文。
- verified_facts：已核验事实列表；每项包含 id、text、quotes、planid、section_path。quotes 是可核对的原文引句。
- coverage：证据覆盖情况，包含 verified（已核验范围）和 missing（缺失或不足的范围）。

## （二）输出契约

- conclusion：先输出 1–2 条研究结论，每条绑定支撑它的 verified_facts。结论归纳事实，不复述成证据清单。
- evidence：在结论之后逐条呈现已核验事实及其引句，让读者能够核查结论。
- limitations：说明缺失、未通过校验或尚不能回答的部分。证据不足时不为凑结构生成主题或结论。

## （三）校验规则

1. 仅对结论类分析块计算证据覆盖率：按句切分后，有有效支撑签名、对应 claim 仍存活且引句非空的句子计为有据句；覆盖率须达到 0.6。
2. 结论中的每个数字 token 必须逐字出现在其支撑事实的引句中。
3. 结论不得引入已核验事实之外的新 planid、政策标题或数字。
4. 未通过校验的分析块不得进入交付答案；未覆盖的部分须在 limitations 中说明。

## （四）来源与本地化

结论覆盖率闸门借鉴 NousResearch/hermes-agent 的 grounded-citations 技能（MIT）。其覆盖率分子是带数字引用或 [unverified] 标记、已声明来源的正文句数，分母是正文句数；低于设定阈值时校验失败。原项目附加引句时要求其出现在抓取文本中，比较时忽略空白、大小写和 Markdown 提取标记。本项目不把 [unverified] 当作通过凭据：无有效 claim 和引句支撑的分析块被拒绝，不输出其正文；覆盖率按有据分析句数除以分析总句数计算，低于 0.6 即拒绝该块。

先给结论、再展开证据的顺序借鉴 stanford-oval/storm（MIT）先生成提纲、再据提纲与资料写正文的组织方式。这里只借鉴顺序，将结论块前置；不引入 STORM 的四个模块、软件包或新增依赖。本项目按 chunk_id 和 claim 记账，不使用 Hermes 的 URL 台账。
