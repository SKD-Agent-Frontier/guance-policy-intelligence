# 政策比较与多方案分析

本目录提供 `compare`（政策异同）和 `compare_plans`（优势、限制、适用条件）两个业务模块。
共享比较矩阵和证据对齐流程；不构造 Runtime、RAG Store、模型客户端或最终 RunResult。

## 工作流程

1. 使用注入的模型服务解析主题、维度和用户明确评价标准。
2. 按完整目标集合调用 search/read，先取得各对象身份，再轮流回读片段，遵守工具和时间预算。
3. 模型根据给定证据生成简洁事实和分析依据；程序验证对象绑定、证据编号和数字，回填原文引用。
4. 生成矩阵与分析，交给基础层统一核验；单元格缺证则撤回相关异同或优势判断。

政策对比默认维度为发展目标、政策工具、适用对象；方案分析默认维度为适用对象、支持措施、
申请或执行条件。显式 dimensions 优先。正常请求两次模型调用；完全无正文时不再调用分析模型。
取证上下文最多 12000 字，按对象均分；每个对象最多回读三个片段/章节，不声称全文覆盖。

通过共同范围检索和逐对象原文回读保障覆盖，绝不修改 ctx.scope。主题进入 query；类型元数据
仅用于说明候选对象性质，不冒充全库类型过滤或事实依据。对不同性质、时期和数量口径明确说明限制。
没有明确评价标准时不自动评分、排名；即使提供标准也不生成无条件最佳方案。

## 接口与交付

通过统一入口调用：

```python
result = await submit(
    "比较两份人才政策的支持措施和适用对象，说明比较口径限制",
    task_type="compare",
    targets=["37982", "38366"],
    dimensions=["支持措施", "适用对象"],
    settings=settings,
)
```

多方案调用改用 `task_type="compare_plans"`。两个编号对应当前发布库中的真实人才规划，
具体事实与输出以实际运行结果为准，不将规划安排表述为补贴申领指南。
输出字段详见 [SCHEMA.md](SCHEMA.md)。事实 Claim 和分析判断分开保存；底座清空结构化结果时不绕过。

单元测试位于 `agent/tests/test_compare.py`，使用明确标注的合成数据和模拟模型。
真实验收脚本为 `agent/scripts/live_compare_acceptance.py`；需本机学校模型配置、恢复后的真实运行库，
依次执行两类功能、跨期和受控缺证场景。成功后才写入真实 `sample.json`。

## 已知限制与维护记录

- 只接入现有原生文本取证能力；不增加 OCR、图片、前端或文档导出实现。
- 无法唯一定位的自然语言对象需用户澄清，不从搜索前几名擅自挑选政策。
- 有限检索无法证明某篇政策没有条款；不输出 not_in_document。
- 当前底座任一 Claim 失效时整体清空矩阵；逐格保留由后续共享契约统一处理。
- 语义分析使用模型，确定性核验不保证引文在语义上充分支持结论。真实验收需逐项审阅。
- 本轮因跨地区唯一标题定位、compare_plans 最少对象数和多对象引文数量直接影响功能接入，
  对共享层作最小调整；不开展其他底座优化。
- 真实模型配置当前待提供；真实运行样例和完整验收尚未完成，不将离线结果标记为产品验收通过。
