## 一、本数据集是什么

本数据集是**校内规划文本数据库（PlanDB）的分层代表性样本**，供参赛队开发与调试智能体使用。

| 项目 | 数值 |
|---|---|
| 收录篇数 | **506 篇**（代表性样本 400 篇 + 边界压力样例 106 篇） |
| 文件总数 | **1,655 个** |
| 解压后体积 | **586.6 MB**（压缩包约 **456 MB**，便于传输） |
| planid 范围 | 57 – 57342（跨越全库首尾） |
| 覆盖上级行政区 | 184 个（含 44 篇省级、19 篇国家级） |
| 全库规模（对照） | 53,161 篇 · 113,657 个文件 · 约 55–77 GB |

> ⚠️ **重要：本数据集只是开发样例，不是全库。**
> 参赛队交付的智能体最终将接入**全库（53,161 篇）只读访问**运行。样本的作用是让各队在开发期快速搭通链路、理解数据形态；所有功能与性能指标必须在**全库**上验证。

## 三、数据来源与合规

- **来源**：中国社会科学院大学经济学院「规划文本数据库」（PlanDB）——国内人文社科领域规模较大、体系完整的政策文本数据资产。
- **内容**：全国各行政区域**各级政府公开发布**的五年规划纲要、专项规划、政府工作报告等。
- **合规**：全部为正式公开发布文件，**不含个人隐私、无涉密风险**。
- **使用约定**：
  1. 数据仅限本次大赛使用，**不得外传、不得用于大赛以外用途**；
  2. 对外发布成果引用内容，以公开发布文件为准；
  3. 全库只读账号口令仅向参赛队伍提供；
  4. 评测期间数据库已做**备份快照**，任何写操作将被拦截并可按快照回滚。

## 四、数据格式说明（★ 回应外审专家第一问）

外审专家提问：*「需要确定数据格式，如 PDF 需确定是否包含大量图片、是否需要 OCR、是否需要统一处理。建议先确定目前的数据格式有哪些？存储的类型和格式是什么。」*

以下为**全库实测口径**（非估计值，可由 `metadata/reproduce/` 脚本复算）。

**（3）正文可得性**（这是本赛题最关键的一张表）

### 4.2 关于 OCR：本库**不需要大规模 OCR**

- 本库文本来自**政府网站公开发布的电子原生文件**（HTML / Word / PDF），**不是扫描件**。
- 实测**仅 609 篇（1.1%）**无正文文本，其中绝大部分是少量纯扫描 PDF 与早期存档件。**OCR 的目标是这 609 篇，而不是 12,248 个 PDF 文件。**
- 换言之，**「扫描件 OCR」不是本赛题的主要矛盾**；主要矛盾是**格式版本不齐**与**结构化程度不一致**（见 §6）。这一点与通用赛题模板的假设不同，请各队注意。

### 4.3 正文体量（用于容量规划）

| 指标 | 数值 |
|---|---|
| 正文总字数 | **12.17 亿字** |
| 平均篇幅 | 22,885 字/篇 |
| 最长篇幅 | 538,804 字 |
| 正文净体积（UTF-8） | 约 3.6 GB |
| 离线检索索引（SQLite FTS5 trigram） | 约 25 GB |

> ⚠️ **澄清**：赛题原文中「全文与元数据累计数十 GB」的表述容易被误解。实际**正文净体积约 3.6 GB**，数十 GB 主要是**检索索引**占用。各队做容量规划时请以正文体积为准。

### 4.4 图片与表格的处理责任（★ 回应专家第二问）

专家要求：*「文本中的图片、表格由参赛方自行处理（如图片采用多模态识别、表格转写为 Markdown 或结构化数据），并随提交物说明处理方式，该部分计入评测口径。」*

本数据集的对应安排：

| 对象 | 提供形式 | 参赛方需做什么 |
|---|---|---|
| **表格** | 已转写为 **Markdown 表格**置于 `{planid}.md`；原始 `<table>` 保留在 `{planid}.html` | 按需进一步结构化为 JSON/DataFrame；须说明处理方式 |
| **图片** | 置于 `media/`，**emf/wmf 矢量图已统一转为 png** | 多模态识别 / OCR / 图文对齐，计入评测口径 |
| 图文位置关系 | `{planid}.md` 中图片以 `![图N](media/imageN.png)` 内联于原文对应位置 | 可据此做图文对齐 |

已完成的预处理（避免系统性失分）：**11 个 emf/wmf 矢量图已转换为 png**。矢量格式多数多模态方案无法读取，若原样下发会造成与「由参赛方处理」表述矛盾的失分。

### 4.5 关于去重

专家要求：*「知识库的文本文件要做去重处理。」*

本数据集已核查：506 篇**篇级不重复**（planid 唯一）。但请注意，全库中存在**内容高度相似的篇目**（如各区县「十四五」专项规划模板化程度高、上级规划的下位重复表述），**片段级近重复需由各队在切片阶段自行处理**，并说明去重策略——该部分计入评测口径。

## 五、抽样方法（可复现）

### 5.1 分层维度

按 **3 个维度**分层，配额用**最大余数法**按全库比例分配，并做下限修正与省域扩散上限：

| 维度 | 取值 |
|---|---|
| 行政层级 | 国家 / 省 / 市 / 区县 |
| 规划期 | 十四五 / 十三五 / 十二五 / 十一五 / 政府工作报告 / 十五计划 / 其他 |
| 规划类型 | 总体规划纲要 / 专项规划 / 其他 |

- **随机种子**：`20260914`（确定性，结果可完全复现）
- **省域扩散上限**：同一地级市/省不超过 22 篇

### 5.2 代表性样本 400 篇的构成对照

| 维度 | 样本占比 | 全库占比 |
|---|---|---|
| 行政层级·区县 | 56.3% | 58.2% |
| 行政层级·市 | 31.3% | 32.4% |
| 行政层级·省 | 7.8% | 8.6% |
| 行政层级·国家 | 4.8% | 0.8% |
| 规划类型·专项规划 | 83.3% | 87.8% |
| 规划类型·总体规划纲要 | 14.8% | 12.1% |
| 规划类型·其他 | 2.0% | 0.08% |
| 登记格式·docx | 47.0% | 45.6% |
| 登记格式·html | 32.8% | 31.3% |
| 登记格式·pdf | 20.3% | 22.6% |

> 国家层级与「其他」类型做了**刻意过采样**（全库占比极低但研究价值高），其余维度与全库偏差均在 **±2 个百分点**内。

### 5.3 边界压力样例 106 篇

| 规则 | 篇数 | 考察点 |
|---|---|---|
| E1 超长文档 | 15 | 切片策略、上下文窗口溢出 |
| E2 HTML 空壳（正文须从 PDF 取） | 20 | 多来源取正文、容错 |
| E3 图片密集 | 15 | 多模态处理、图文对齐 |
| E4 极短文档 | 15 | 低信息密度、检索噪声 |
| E5 早期规划期 | 15 | 时代术语差异、口语映射 |
| E6 超长 HTML | 10 | 解析性能、内存 |
| E7 仅有 Word 原文 | 1 | 单一格式兜底 |
| E8 其他补充 | 9 | — |
| **缺陷样例（无正文）** | **6** | **优雅降级：应提示而非报错或编造** |

### 5.4 测试集隔离（★ 回应专家验证集/测试集要求）

| 集合 | 篇数 | 是否公开 | 用途 |
|---|---|---|---|
| 代表性样本 `corpus/` | 400 | ✅ 公开 | 开发调试 |
| 边界样例 `edge_cases/` | 106 | ✅ 公开 | 鲁棒性自测 |
| **held-out 测试池** | **300** | ❌ **不公开** | 由发榜单位保留，用于生成正式测试集 |

held-out 测试池与公开样本**零重叠**（算法保证：抽完公开样本后从剩余篇目中独立抽取）。测试集在评审阶段离线评测，不随本包下发。

## 六、已知缺陷与边界情况（★ 请各队务必阅读）

诚实披露数据缺陷，是避免各队把「数据问题」误判为「自己解析失败」的前提。

| # | 问题 | 规模 | 各队应对 |
|---|---|---|---|
| 1 | **HTML 空壳**：部分 `{planid}.html` 仅有标题、无正文（几十字节） | 全库 11,977 篇（22.5%）；本包 122 篇 | 判空后**回落到 `{planid}.md` 正文**（本包 `.md` 已做兜底：`content_source: dbtxt`） |
| 2 | **无任何正文** | 全库 609 篇（1.1%）；本包 6 篇 | **优雅降级**：明确告知用户该文件无可用正文，严禁编造 |
| 3 | **Word 原文缺口** | 全库登记 24,237 篇，磁盘仅 14,785 个 | 原文**非稳定可得**，正文请以 `.md` 为准，不要依赖 `origin/` 必存在 |
| 4 | **矢量图** | 全库 emf 366 + wmf 101 | 本包已转 png；接入全库时需自行处理这两类格式 |
| 5 | **元数据缺失** | 部分篇目 `fyp_name` 为空、`city` 缺失 | 过滤/统计时需容忍空值 |
| 6 | **模板化重复** | 区县级规划高度模板化 | 切片阶段做近重复检测 |

### 6.1 本包的收录取舍规则（透明披露）

为把体积控制在便于分发的范围内，`origin/` 层做了如下取舍，**未收录的文件全部记录在 `metadata/file_manifest.csv` 的 SKIP 行中并注明原因**：

| 规则 | 说明 |
|---|---|
| PDF | **仅当该篇无真实 HTML 正文时收录**（否则正文已由 HTML/`.md` 覆盖，PDF 冗余）；单文件 ≤ 15 MB |
| Word | 单文件 ≤ 8 MB |
| 图片 | 单篇总量 ≤ 10 MB，按体积降序收录 |
| 矢量图 | emf/wmf 统一转为 png |

> 若某篇的原文因上述规则未收录，其**正文与结构信息不受影响**（`.md` 与 `.html` 完整保留）。研究确实需要某篇原文时，可向发榜单位申请。

## 七、如何用本包搭起索引（建议流程）

1. **建索引主源**：`corpus/*/*.md`（506 个文件，UTF-8，YAML front-matter 可解析元数据）。
2. **切片**：按 Markdown 标题层级（`#` 篇 / `##` 章 / `###` 节）切分，天然对齐「片段级引用溯源」所需的最小引用单元。
3. **元数据入库**：解析 `{planid}.md` 的 front-matter 或读 `metadata/sample_plans.csv`。
4. **表格与图片**：按 §4.4 处理，并记录处理方式（计入评测）。
5. **边界自测**：跑 `edge_cases/`，重点验证 §6 的 6 类缺陷是否优雅降级。
6. **上全库验证**：样本上跑通后，接入全库（53,161 篇）复测召回率与响应时间。

## 九、附：可复现性说明

| 脚本 | 作用 |
|---|---|
