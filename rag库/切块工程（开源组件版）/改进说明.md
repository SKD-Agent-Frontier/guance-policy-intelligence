## 1. 本次改什么

将父子块的通用递归切分和层级关系生成，交给 **LlamaIndex `HierarchicalNodeParser`＋`SentenceSplitter`**。项目保留原文坐标、政策结构约束、必要关联、图片登记和确定性校验。

原工程自行实现 `make_parents`、`make_chunks`；新版不复制这两个函数后换名，也不另写一套递归切分与贪心拼块算法来替代开源核心。开源切分结果先作为候选，经原文映射和完整性检查后才成为可用对象。

本轮交付仅为本说明及 README。原工程、原始 Markdown、图片和已有批次均不改动。

## 4. 开源组件选型和分工

### 4.1 拟采用 LlamaIndex 的本地解析组件

`HierarchicalNodeParser` 可以按层级调用节点解析器，并建立父子关系；本工程拟配置父、子两层。[官方接口](https://developers.llamaindex.ai/python/framework-api-reference/node_parsers/hierarchical/) · [官方源码](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/node_parser/relational/hierarchical.py)

每层使用 `SentenceSplitter`，通过其 `tokenizer` 参数接入固定的 Qwen 分词器。采用 `node_parser_ids` 与 `node_parser_map` 配置各层解析器，不假设 `HierarchicalNodeParser.from_defaults` 能直接接收任意 tokenizer 参数。[官方接口](https://developers.llamaindex.ai/python/framework-api-reference/node_parsers/sentence_splitter/) · [官方源码](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/node_parser/text/sentence.py)

中文句终、分号和段落边界拟通过组件公开的 `paragraph_separator`、`secondary_chunking_regex` 等参数适配，并测试 CRLF；不能直接假设默认英文句段配置适合本库。实施时保存实际参数及其来源。

这套选型面向本地切分，不需要为切分启动向量数据库、计算 embedding 或调用生成模型。实施时先验证包版本、接口兼容性、离线资源和依赖，再固定版本与来源；本轮尚未安装，不能填写“已验证版本”。

本轮不同时引入第二套切分框架。LangChain `ParentDocumentRetriever` 是另一种可用路线，但还承担文档/向量存储与父文档回取；本阶段选择直接使用节点解析组件。[LangChain 官方接口](https://reference.langchain.com/python/langchain-classic/retrievers/parent_document_retriever/ParentDocumentRetriever)

### 4.2 开源负责什么，项目仍负责什么

| 职责 | 计划承担方 | 边界 |
|---|---|---|
| 通用递归切分、句段组织、父子层级关系 | LlamaIndex 官方组件 | 通过公开接口配置，不复制或修改其核心切分实现 |
| Markdown 结构线索 | `markdown-it-py` | 解析器渲染结果不能代替原文 |
| 中文行内编号、条文、引导语与列表的边界约束 | 项目适配层 | 保存判断依据和范围；只限定输入与审核候选，不另写通用拼块器 |
| 原文读取、快照、全文件码点坐标、确定性 ID | 项目适配层 | 核对开源节点的局部坐标，转换为全文件坐标 |
| 定义、条件、例外、跨条引用、共享表头 | 项目适配层 | 独立记录可追溯上下文；不凭文本相似度猜目标 |
| Qwen 分词 | 官方 tokenizer | 切分预算与最终完整输入计数分别记录 |
| 图片登记、输出、恢复、异常与校验报告 | 项目工程层 | 可复用旧工程已验证的通用能力，但需明确来源并重新测试 |

未来产物需记录组件名称、版本、调用参数及各块的生成路径。直接来自开源、保留完整保护单元、因约束转待处理，分别标记，不能把项目适配或保留整段的结果全部标成开源自动切分。

## 5. 新版拟采用的流程

```text
只读输入、保存原始字节与哈希
    ↓
建立全文件坐标、Markdown 线索和政策保护范围
    ↓
按可靠章节/条文范围交给开源层级切分组件
    ↓
取得父子候选、层级关系与节点位置
    ↓
映射回原文，检查完整单元与引导语约束
    ↓
装配必要上下文，按 Qwen 官方模板重新计数
    ↓
输出可用块、待处理块及同源对照报告
```

开源组件本身并不能保证中文政策结构正确。拟采用下列适配规则，具体效果在用户指示开始后通过样例验证。

| 内容 | 输入和完整性约束 |
|---|---|
| 普通章节 | 先确定可靠章节范围，再交给组件；子块不跨已确认的章节或父块 |
| 同一行的多个小节 | 仅建立带原文位置映射的识别视图；结合连续编号及上下文确认边界，不向源文件补换行 |
| 完整条文 | 保留完整条文父级上下文；对库返回的更小父候选，必要时保留条文保护范围并明确标记适配来源 |
| 引导语与列表 | 先确认引导语、列举范围和共同条件；不能独立发布只有引导语、或缺失其必要条件的项目子块 |
| 表格 | 整表父块保留；完整输入在硬上限内时优先整表子块，不让通用句段切分器穿过单元格 |
| 超长表格 | 仅在可靠逻辑行组处使用开源组件组织候选并带回表头；合并单元格关系不清或行组仍超限时转待处理 |
| 无可靠结构、乱码、空正文、纯图片、仅标题 | 保留来源及原因，不靠开源切分结果生成虚假文本证据 |

若候选切穿受保护单元，先尝试以完整保护范围作为输入重新调用组件；仍不满足约束时，该完整单元在硬上限内可作为保留块，否则转待处理。所有候选调整及原因留痕，不新增隐藏的自写递归切分兜底，也不静默转回旧版核心。

## 6. 原文与长度：继续遵守的硬要求

### 原文位置

- 按字节读取，严格 UTF-8 解码；保留 CRLF、空格、标点和非 BMP 字符。
- 坐标以包含 front-matter 的完整解码字符串为准，使用 Unicode 码点、0 起点、左闭右开。
- 开源节点文本只提供候选。最终 `source_segments` 必须逐字等于 `source_text[start:end]`，不能直接把经过裁剪或重排的节点文本当原文。
- 逐层核对文档、保护范围和父节点的坐标基准；不能假设子节点下标已经是完整文件下标。
- 重复文本结合输入范围、父节点范围和顺序位置映射；不能依靠全文第一次字符串匹配。位置不唯一或内部文本改变且无法准确映射时转待处理。
- 库去掉的首尾空白也要在全文基础单元中保留；不连续的上下文分范围保存，不拼成伪造连续原文。

需要特别验证的官方行为：`SentenceSplitter` 会在后处理中去除块首尾空白，并在必要时采用更细的分隔方式，包含字符级回退。因此，换用该组件不等于自动获得逐字保真和完整条文保护；必须增加上述范围核对与边界检查。[对应官方源码](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/node_parser/text/sentence.py)

### 长度参数

| 参数 | 拟沿用值 | 在新版中的含义 |
|---|---:|---|
| 子块目标 | 约 768 token | 完整检索输入的组织目标；库内候选预算需考虑已知标题、模板等开销 |
| 父块参考 | 约 3072 token | 通用层级切分的参考；完整条文、列表和表格可因完整性要求超过 |
| 完整输入硬上限 | 8192 token | 标题、正文、必要上下文、指令模板及特殊 token 全部计入 |
| 固定重叠 | 0 | 同级块不额外设置固定滑窗重叠；父块包含子块属于层级关系 |

库内部 `chunk_size` 具有自身的长度限制语义，不能直接等同于方案中的“完整单元优先”的软目标。拟通过公开参数配置候选预算，完整单元例外另行记录；最终以实际 Qwen 完整输入重新计数为准。必要上下文加回后超限时，只允许在安全边界重新调用组件或转待处理，禁止截断。

拟核对并复用旧版固定修订的 tokenizer 文件，不重复下载 8B 权重，也不调用模型处理政策原文。当前尚未复制缓存或建立新环境。

## 7. 后续实施、对照与验收

以下工作均在用户查看本说明并指示开始后执行，本轮没有执行。

1. **建立独立环境和配置。**固定开源包版本、依赖、许可证/来源、tokenizer 修订和参数；保留旧版运行基线。
2. **先做同源样例。**复用原有 10 篇固定样例，增加 `34457`、`50143` 和仅标题的 `38501`；补充 CRLF、非 BMP、重复句、中文列举及长度边界用例。
3. **记录开源实际作用。**保存组件调用、节点原始身份/层级、范围映射和约束调整，能查出每个父子块从哪里产生。
4. **生成新旧对照。**在相同输入下展示父子范围、结构路径、完整性、token 数和待处理原因；重点检查已发现的两处问题。块数更多或更少都不能单独证明更好。
5. **按确认范围运行全量。**样例发现的问题先修正并验证，再处理全部输入；单篇失败有记录，其他文件继续。
6. **独立校验并交付。**检查输入未改、全文基础单元覆盖、父子归属、关系有效、必要上下文、完整输入上限和恢复一致性；输出真实数量和限制。

“结构约束检查通过”和“检索效果提升”分别报告；本轮及后续纯切块验证均不能替代检索问答评测。不增加全量生成模型审核或逐块人工签字门槛。
