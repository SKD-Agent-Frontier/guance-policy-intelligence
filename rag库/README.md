## 安装与启动

三个正式工程保留原目录名称及相邻关系；语料库保持仓库根目录下的`语料库/Agent标准引用库`。不要将检索工程单独复制后当作完整知识库。

新环境按各工程的依赖锁安装；检索所需依赖可使用本地存储工程的`requirements.lock.txt`，并在同一环境执行`python -m pip install -e ./rag库/检索工程`。向量模型和OCR服务的实际地址、凭证通过被忽略的`secrets.local.json`配置，示例文件不含可用凭证。

在仓库根目录、已有运行数据和本地环境时，可启动常驻接口：

```powershell
& '.\rag库\向量化与存储工程（降级版）\.venv\Scripts\python.exe' '.\rag库\检索工程\run.py' --mode bm25 serve
```

`serve`使用标准输入输出逐行JSON，不是HTTP服务。`bm25`不调用向量模型；需要图片向量召回时使用`hybrid`，并准备同一向量空间的服务配置。混合模式实测约79秒启动、峰值工作集约9.46GiB，见[多模态验收](检索工程/多模态验收报告.md)。

## GitHub源码与本地运行数据

Git保存源码、配置模板、依赖锁、契约、样例和验收摘要；统一忽略虚拟环境、缓存、数据库、正式输出批次、本地密钥及ZIP。目录内的`outputs/README.md`仍纳入Git，用于说明本地批次。

**克隆仓库不等于获得已经建好的RAG库。** 检索运行还需要本地存储工程中的`.runtime/local/`和当前发布引用的`outputs/prepared_*`、`media_*`、`local_generation_*`，以及匹配的tokenizer/模型profile；其中冻结Markdown和图片用于原文、原图回取。数据应通过备份/恢复单独交付，并核对文件哈希和清单中的路径，不能只传SQLite或只传向量文件。

2026-10-24完整运行数据单独发布在[同仓库 Release：rag-v0.4.0-data-20261024-r1](https://github.com/SKD-Agent-Frontier/guance-policy-intelligence/releases/tag/rag-v0.4.0-data-20261024-r1)。附件为512MiB分卷（末卷较小）、交付清单和SHA-256；包含当前SQLite、Qdrant Local、BM25S、冻结原文／图片、OCR结果及当前输入向量缓存。使用[恢复工具](向量化与存储工程（降级版）/restore_delivery.py)恢复到新目录，详细步骤与验证边界见[运行数据交付说明](运行数据交付.md)。私有模型服务地址和密钥由接收方在本地配置，原文、图片、OCR正文及向量不重算。

原始语料库用于重新切块和建库，继续与`rag库`同级，不在RAG模块下重复复制。冻结快照是已发布证据版本，承担回取和校验用途，不能因与原始资料相似就删除。

## 历史资料及本次整理边界

[历史资料目录](历史资料/README.md)保留原PostgreSQL/Qdrant Server源码、历史切块评估及1.0设计，不属于当前Agent运行主线。旧ZIP只在本地保留，Git忽略；以展开的当前文档为准，旧Agent对接ZIP缺少最新媒体接口。

本次仅归档旧PostgreSQL工程的42个Git文件。其旧数据库、环境、缓存及大批次保持本机原路径`rag库/向量化与存储工程/`，整个旧路径由Git忽略；`config.json`与`当前批次.json`留有原字节副本，供本地存储工程已有`migration_source`读取旧冻结数据。该路径是本地数据来源，不是另一套待提交源码；不应把`migration_source`改为只含源码的归档目录。

当前切块、本地存储、检索和原始语料路径不移动；本轮不重新切块、OCR、计算语料向量或修改发布身份，也不启动、停止或迁移旧数据库服务。历史报告中的原路径、时间和验收范围按当时含义保留；本次目录整理不代表重新完成历史数据库验收。
