# 检索设计方案 2.0（Agent 对接修订）

修订日期：2026-10-23。自写切块、本地建库及既有检索命令已实现；**本文件新增的常驻 KnowledgeBase 适配、分页工具和扩展证据校验仍待实现**。本轮真实核查及样例见 [Agent 对接说明](Agent对接说明/README.md)，实现差异见[差异清单](Agent对接说明/差异清单.md)。上游：[向量化与存储设计方案](向量化与存储设计方案.md)；返回[方案概要](RAG库技术方案概要.md)。

## 1. 简化后的检索链

> 问题与明确筛选 → BM25＋向量召回 → RRF 融合 → 父块及必要关联回取 → 回答与引用校验。

当前按用户后续选择接入 **SQLite＋Qdrant Local＋BM25S/jieba**，保留 MetadataStore、VectorStore、LexicalStore 独立接口及既定 Qwen 服务；原 PostgreSQL/Qdrant Server 工程保留。两路使用同一冻结发布与过滤条件，不重新切分上游父子块。父块沿用现有 parent_id 直接回取，不引入第二套 LangChain 块或章节编号。文本子块和可用识别文字走词法与向量两路，纯图像只走向量路；旧 Agent 未扩展媒体类型时显式限定 text_chunk，不冒充全模态接入。

去掉独立重排模型、自动研究任务拆解、循环补取、近重复候选池和复杂跨来源折叠。原有离线重复关系保留，在线只合并同一来源单元的多路命中，同一父块回取一次；不同文件继续保留各自出处。

每路候选数沿用当前 `max(20, top_k*4)` 起点；目标是同一 source_id 的多种表示在同一路先取最好名次，再以 `Σ 1/(60＋名次)` 融合，避免重复加分。**现有 query 按 representation 融合、最后按 source 去重，该合并顺序仍需修正。** Agent 默认 top_k=8、上限20；预算不足时减少返回量并说明原因，不循环扩搜。不同来源文件仍分别保留出处，score 不作为政策支持概率。

## 2. 筛选与完整证据

- 使用明确的 planid、地区、时期或文件类型条件；元数据未知不视为满足硬条件，不混淆发布日期、报告年份与目标年份。Agent area 映射 area_name，fyp 映射 period_key/fyp_name；地区包含匹配先根据真实元数据得到允许集合，不猜行政区划。现有接口多为等值过滤，包含匹配适配仍待实现。
- 两路都在符合条件的集合内选 Top-K；结果再核对来源和条件，不能先截全库结果再过滤。
- 已知片段或原文范围时直接读取；一般查询先用子块定位，再回取同版本父块及规则明确解析的必要关联。
- 共同条件、否定、例外、表头和单位用带来源范围的 contexts/relations 提供，不能拼进主 content 后冒充一段连续原文。完整覆盖发布保留原 status/reasons 和质量提示，已有 pending 块不因此自动失去召回资格；依赖未解决的候选仍标记上下文不足，不单凭金额句生成结论。
- 按回答模型实际预算装配证据。父块过长时，只选能保留完整条件的既有单元及其关联；仍装不下则说明不足，不截半个条文或表格。
- 明确比较多个对象时分别检索、分别列出处；一方缺证据就写明缺口，不自动扩展比较维度。

图片证据同时回取原图及区域，识别文字标明派生性质。若回答模型不能读取图片，只展示图片入口及不确定说明，不仅凭向量命中推断图中事实。

## 3. 引用生成与校验

沿用RAG的chunk_id作为来源身份，不用Agent自编编号、向量point_id或representation_id替换。run内证据记录另存文档版本、批次、offset_basis、body_origin、完整块范围和已提供模型的范围；如使用evidence_id，它是证据记录身份，不替换chunk_id。模型只使用返回的来源编号；标题、位置、引句和原文入口由程序真源生成/校验，不由模型补造。

当前 Agent 已做登记 ID 过滤，但 Claim.quotes 尚未逐字核对，同 chunk_id 的再次读取还会覆盖之前范围。下表是接入目标，不能将其全部称为现有能力；证据登记应合并 observed_ranges，只批准模型引用已提供范围，块的未读部分不能因 ID 存在就被引用。

| 项目 | 本版要求 |
|---|---|
| 身份 | 引用必须属于本次提供的证据，不接受模型编造的编号 |
| 文本原句 | 按快照哈希及offset_basis/body_origin将已见范围换回文件坐标，取回并逐字校验；检索前缀和模型解释不是原句 |
| 图片及 OCR | 原图存在、区域和识别版本可定位；展示原图及识别标识，不把 OCR 当作原生文本 |
| 上下文 | 结论与对象、地区、时期、条件、数值单位和例外一致；证据不足时收窄结论或明确说明 |
| 展示 | 引用可打开冻结版本并定位；当前只有本地快照路径，没有已部署原文HTTP服务；没有真实页码、章节或官方链接时不编造 |

文本位置正确不等于结论受到支持。回答模型根据已提供的父块和必要关联组织有依据的回答，不增加独立的逐条大模型复核调用或人工审核步骤；程序负责可确定的身份、位置、文本和关联校验，不能把这类检查报告为语义正确性保证。

不同事实分别引用，条件和金额来自两处时两处都标注。政策原句与分析分开呈现；本地来源可追溯不自动等于官方认证或现行有效。

## 4. 输出与验证

输出回答、引用、来源信息、原文或原图入口、实际筛选条件及证据不足说明。未命中表示本次范围内未找到，不表示政策不存在；索引故障单独报告检索失败。

用固定样例验证明确条款、否定与数字、同句多处出现、父块共同条件、跨条依赖、表格和图片、不同地区同文、旧版本引用及无证据问题。自动检查：

1. 引用身份、来源、文本范围或图片区域有效，失效引用不进入最终输出。
2. 子块回取正确父块，已解析的必要关联没有遗漏，最终证据不被预算处理截坏。
3. 已有预期原文范围的样例命中相应证据；仅有文档编号的题库只用于文档级召回检查。

报告程序校验结果、固定样例结果和未解决问题，不强制全量模型或人工复核，也不把定位通过率称为回答准确率。2026-10-23本轮已核查506篇快照哈希、42,516个原生块范围及ID重算，导出真实BM25命中与原文样例，并验证长块分页重建。尚未进行常驻适配、启动加载次数、并发、真实问答或历史跨版本验收，也未重跑dense/混合效果评测。详见[核查结果](Agent对接说明/核查结果.json)。

## 5. Agent 接口与启动共享

当前 RAG 是同步 `query(project,text,limit,mode,filters)` 及对象回取，返回嵌套 dict；尚无匹配 Agent 的真实 KnowledgeBase，也没有 HTTP 服务。目标继续使用同步适配器，由 Agent 异步工具调用：

```python
search(query, area, fyp, top_k) -> list[HitV03]
read(planid, section_idx, max_chars, *, chunk_id=None,
     offset=0, document_id=None, generation_id=None) -> PassageV03
```

启动阶段在一个专用库工作线程中固定active generation，建立只读SQLite查询连接，加载成员、冻结章节目录、BM25S和所需dense集合，并按文档版本计算和缓存body_origin。完成后才ready。多个请求共用同一运行时，以有界队列交给库线程，首轮库操作串行；证据登记仍按run隔离。

不把启动线程创建的现有 SQLite connection 任意交给 to_thread 线程池；Qdrant Local 也保留线程/路径锁约束。运行时持有既有项目锁与 Qdrant 锁，一个目录不能由多个 Web worker 各自打开，不能删除锁绕过限制。业务只读冻结索引，SDK锁/WAL维护及独立问题缓存不伪称文件系统绝对零写入。

当前 CLI 每次开关库，MockKB 也是首次使用才缓存，不满足上述目标。整库此前有约9.76GiB冷加载峰值记录，应在启动预留资源，不将冷加载放进首次工具请求。排队和后端执行设各自时限；to_thread等待超时不代表已终止后台任务。发布更新通过受控关闭/重新加载，单次请求不混读两个版本。

## 6. 身份稳定性与统一原文坐标

实际 ID 为 `kind + '_' + SHA256(紧凑UTF-8 JSON(parts))前32位`，按项目全库使用并以主键/内容冲突约束：document_id绑定planid与source_hash；parent_id绑定文档、范围及config_hash；chunk_id绑定文档、父块、原文范围及config_hash。当前config_hash还包含tokenizer及代码原始字节指纹，注释变化也可能产生新ID。

复用同一冻结切块产物重建向量/BM25或迁移存储，chunk_id保持原值；**重新切块不能承诺ID无条件稳定**。历史引用保存chunk_id、document_id、source_hash、generation_id、offset_basis/body_origin及实际引用范围，保留旧对象、快照和目录，不因新索引上线自动清理。旧记录按原契约解释，不将旧文件坐标直接视为正文坐标。原切块document_id与向量工程document_version_id是两个既有映射字段，不互换表主键。

| 字段 | 语义 |
|---|---|
| chunk_char_start / chunk_char_end | 原生完整块在正文坐标中的固定范围 |
| char_start / char_end | 本次 content 在正文坐标中的实际范围，随预览/分页变化 |
| offset_basis / offset_unit | body_first_non_whitespace / unicode_codepoint |
| body_origin | 正文首字符在完整MD中的绝对码点位置，用于坐标换算 |
| body_start | 原有元数据字段：头部元数据结束位置，可能早于 body_origin，不直接作为新原点 |
| section_id / section_path | 原父块 structure_id / 真实标题路径 |
| generation_id、document_id、source_hash、snapshot | 发布、版本及冻结原文定位 |

**对外坐标口径：跳过头部元数据及正文前面的空白，正文首字符记为0；从这里往后所有字符都保留并计数，包括空格、换行和Markdown符号。chunk_char_start/end与char_start/end使用同一原点，采用0起点、左闭右开、Unicode码点。** 章节范围、页内块范围和文本上下文范围也使用同一正文坐标，不混入文件绝对坐标。

原文仍从冻结MD字节严格UTF-8解码，不做通用换行转换。body_origin从原有body_start开始，仅向后跳过开头满足Python str.isspace()的字符；无头部元数据时跳过文件首BOM（若有），再跳过开头空白。正文内部的CRLF、空白和Markdown符号原样保留；正文全为空白时原点为文件末尾，按无正文处理。Markdown的首个`#`等符号也是正文字符，不以渲染后的文字重新计数。

令body=source_text[body_origin:]，则content==body[char_start:char_end]，完整块同理；原文件坐标=正文坐标+body_origin。浏览器UTF-16下标必须显式转换为Unicode码点。retrieval_text增强前缀不作为原句；不在content中插入省略号或额外标签。

这次调整由检索适配层在启动时按文档版本计算并缓存body_origin，统一转换对外范围；切块、数据库及冻结快照继续保留原文件绝对坐标，chunk_id/section_id及其生成输入不变，无需迁移数据库、重切或重建索引。内部source_segments和原始查询结果不直接冒充新契约。对外契约标记proposal-v0.3，Agent按offset_basis识别，不能将旧坐标原样套入新正文。正文起点之前的范围不得静默截断为0；根目录对外范围从正文0开始，原始范围仍保留在内部，其他异常范围先拒绝并定位原因。

当前42,516个原生块均为单一连续范围；未来不连续内容必须返回多段source_segments，不能以最小起点/最大终点伪称连续。媒体坐标另分类型，OCR转录码点不填写MD正文坐标，bbox保留coordinate_basis、原尺寸及识别版本。

## 7. 章节目录、按块回看与续读

章节真源为原父块structure_id；空路径不编造标题。当前RAG没有持久化section_idx，适配时按(start,level,id)冻结文档目录、root=0；idx仅在固定generation/document目录内有效，引用绑定section_id和版本。当前全量核查未发现块内部跨已识别章节边界，但不等于人工确认所有标题识别正确。补充parent_context与原父块分别保留，不覆盖主块的原始章节归属。

chunk_id可经SQLite objects.id主键直接查source_segments及document_id，再回取版本快照和章节，不需扫描chunks.jsonl。验证对象类型及planid归属，错误归属为invalid_argument，未知对象为not_found，只有无正文文档才是no_text。

| read输入 | 返回 |
|---|---|
| 无section_idx/chunk_id | 指定版本的目录，is_index=true、content为空、offset=0 |
| 仅section_idx | 章节内一页，offset相对章首；返回章节ID及全范围 |
| 仅chunk_id | 块内一页，offset相对块首；返回完整块范围及所属章节 |
| 同时给两者 | 校验同一目录与归属，不静默忽略冲突参数 |

max_chars默认6000。完整块能放下则全文返回、truncated=false；超出则返回真实一页、truncated=true及next_offset。offset/next_offset仍为所选块或章节内的相对码点，不因正文原点转换而再减body_origin；输出char_start/end及section_char_start/end统一为正文坐标。负值、非整数或非空范围的越界起点拒绝。Passage.chunks区分完整块范围与本页交集，用complete标明是否整块可见，部分页不得登记为已读全块。

**实测41个原生块超过6000码点，最长91631。** 程序层按chunk_id的完整原文必须可取，用于原文回看/确定性校验；不能保证任意完整块都塞进一次模型响应。Agent按next_offset显式续读，拼接各页应逐字还原原块。分页不恢复自动循环研究/扩搜链。历史会话中旧块如需成为本次证据，重新读取原版本并登记。

新增验收覆盖：启动加载一次、多请求共享与run证据隔离、线程/锁边界、两路预过滤及表示归一、块/章节读取、6000字后续读、错误planid拒绝、正文原点及双向坐标换算、开头空白/内部空白/CRLF/非BMP/重复句定位、可见范围及引句核验、重建索引ID稳定与旧版原文回看。设计及5份Hit/Passage契约样例已对齐proposal-v0.3，文本和ID保留不变；生产转换、续读及常驻适配仍待实施。旧导出脚本、原始RAG结果及核查报告继续保留文件坐标，样例对齐不能作为生产接口运行验收。
