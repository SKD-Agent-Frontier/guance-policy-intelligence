# 切块方案 2.0

日期：2026-10-21。本文为设计，未执行语料处理。返回[方案概要](RAG库技术方案概要.md)。

## 1. 沿用的思路与简化范围

沿用 1.0 的“结构约束＋父子块”：程序识别原文单元及层级，父块保留完整上下文，子块用于检索，必要条件和跨条引用另存关联。

> 原文快照 → 结构识别 → 父子块划分与关联 → 程序校验 → 输出可用结果及异常清单。

取消两阶段全量大模型复核、模型与程序争议清单、人工裁决及其发布门槛。不额外增加逐块模型审核或强制人工检查；程序检查保留，异常有记录、有去向。

输入仍为 `语料库/Agent标准引用库` 下的 `corpus`、`edge_cases`。原文件保持原样，训练集答案与模型生成解释不进入政策证据库。

## 2. 结构识别与父子块

复用 markdown-it-py 提供 Markdown 结构线索，结合行首中文编号、前后层级和顺序识别章节、条文、自然段、列表、表格及图片引用。正文中的“按照第八条执行”不作为新条文，目录不作为政策事实。

| 内容 | 父块 | 子块 |
|---|---|---|
| 条文 | 完整条文及直接相连的说明 | 完整款项或句群，保留所属父块 |
| 引导语与列表 | 引导语、受其约束的项目及共同条件 | 完整列举项；检索输入附带共同条件 |
| 普通报告正文 | 有连续关系的自然段或小节内连续部分 | 完整段落或句群，不跨父块拼接 |
| 表格 | 表题、表头、单位、附注和完整表格 | 优先整表；过长时按有共同约束的逻辑行组表示，保留完整表格父块 |
| 无可靠层级 | 保留自然段及前后上下文，不编造标题 | 沿可靠段落边界切分；仍不可靠则待处理 |

子块不按固定字符数硬截。父块较短时直接生成同范围子块。表格行组的表头、单位和附注可加入检索文本，但每部分保留各自原文范围，不伪装成原文中连续的一段；合并单元格或行列关系无法确定时保留整表或待处理。

相邻的条件、定义和例外尽量纳入父块；“前款”“第×条”等明确引用按同一来源的编号解析并保存关联。无法唯一定位的关联标记未解决，检索时不能把缺失上下文的子块独立当作完整依据。不建设额外的自动推理链，也不凭相似度猜测引用对象。

## 3. 长度与原文保真

沿用 Qwen/Qwen3-VL-Embedding-8B；约 768 token 作为子块目标长度的调试起点。完整单元超过目标但未超过硬上限时优先保留。超过硬上限时只沿完整款项、句群或可靠表格行组细分；无法安全划分则待处理。

使用实际 processor/tokenizer 检查完整 embedding 输入，计入标题、必要上下文和模板，禁止静默截断。父块用于回取，不要求与子块相同长度；回答时另检查上下文预算。

保存原始字节快照及 SHA-256，严格解码并保留换行。范围采用完整解码字符串的 Unicode 码点下标，0 起点、左闭右开。每个原文范围必须满足：

```text
片段原文 == source_text[start:end]
```

多个不连续范围分别记录、分别还原。检索增强文本另存 `retrieval_text`，不充当原句。重复句子按保存的位置取回，不用第一次字符串匹配猜位置。

## 4. 程序校验与异常处理

程序对全部结果执行以下检查，不调用大模型替代确定性检查：

- 基础单元连同元数据、空白等范围能无缺口、无重叠地还原全文；父块和章节允许嵌套，另查包含关系。
- 每段有效正文都有父子块覆盖或明确的待处理原因；目录等排除内容保留范围与理由。
- 原文哈希、片段范围和逐字内容一致；子块属于正确的父块、文档及来源版本。
- 结构包含关系无循环，必要关联指向真实对象；不能唯一解析的依赖保留状态。
- 实际检索输入长度合规；条件、表头等规则要求的关联内容没有在装配中丢失。

空正文、仅标题、乱码、疑似缺页、未解决依赖和超限内容分别记状态。能处理的范围继续输出，异常范围单独保留。程序校验能证明位置与结构约束成立，不能保证全部政策语义完整；回答阶段仍需依据实际上下文判断证据是否足够。

## 5. 数据与交付

| 产物 | 核心内容 |
|---|---|
| `documents.jsonl` | planid、标题、路径、快照、来源哈希、解码方式、元数据和状态 |
| `units.jsonl`、`structures.jsonl` | 原文基本单元、范围、层级及结构版本 |
| `parents.jsonl`、`chunks.jsonl` | 父子 ID、来源版本、原文范围、检索文本、长度和状态 |
| `relations.jsonl` | 条件、定义、例外和跨条引用的目标、规则依据及解析状态 |
| `校验报告.md` | 覆盖、定位、归属、长度检查结果与异常数量及原因 |

来源版本由 `planid＋source_hash` 确定；父子 ID 由来源版本、范围和切分配置确定，重跑可对应，不同文档保留独立身份。未知元数据不补造。

先用条文、列表、表格、断行、跨条引用和异常文件的固定样例验证规则，再运行约定范围。发现问题后修正规则并重跑受影响部分。正式入库条件是程序校验通过、没有阻断使用的已知异常，不再要求模型复核记录或人工签字。
