# RAG 库技术方案 2.0

日期：2026-10-24。状态：自写切块、本地向量化/存储和独立RAG检索已实施；原生文字、OCR及原图召回、read/read_image回取、常驻共享、坐标隔离、分页和原句范围校验已通过工程验收。API为proposal-v0.4，原生文本契约保留V0.3。Agent类型/工具、图片消息、运行内证据登记及端到端问答尚待同事完成。证据见[本地建库](../向量化与存储工程（降级版）/README.md)、[检索工程](../检索工程/README.md)、[多模态验收](../检索工程/多模态验收报告.md)及[交接说明](Agent对接说明/多模态交接说明.md)。

**沿用 1.0 的技术思路，去掉全量大模型复核和人工裁决流程，适度简化检索。** 保留结构识别、父子块、图片处理、去重与向量复用，以及来源版本和原文定位。当前按用户后续选择使用 SQLite＋Qdrant Local＋BM25S；原 Qdrant Server＋PostgreSQL 工程保留。重点仍是切片完整、引用真实可追溯。

## 一、切块方案

程序识别 Markdown 结构、中文编号和原文单元，再划分父块与子块：父块保留完整上下文，子块用于检索；共同条件、例外和跨条引用记录关联。当前自写切块器复用 markdown-it-py 提供结构线索，政策边界与原文定位由项目规则处理；父块按既有 parent_id 直接回取，不引入第二套 LangChain 块身份。

删除“结构全量模型复核—人工裁决—切块全量模型复核—人工裁决”两道审核流程，改为程序直接生成并校验。保留全量原文覆盖、位置、关系和长度检查；规则无法处理的内容记录异常，不以未完成人工审核为入库阻碍，也不自动冒充完整证据。

详见：[切块方案](切块方案.md)。

## 二、向量化与存储方案

沿用 Qwen/Qwen3-VL-Embedding-8B；当前接入本地 SQLite、Qdrant Local 和 BM25S，保留独立存储接口。文本保留父子关系；图片保留原图、识别内容、语义区域及位置映射。向量化前记录精确重复和近重复候选，相同配置与实际输入复用计算，各来源独立保存。当前完整覆盖发布保留质量提示，不因 pending 标签自动丢掉已有子块。

保留来源快照、增量处理、任务重试和校验后切换批次。图片处理同样取消全量模型复核及人工裁决，保留资源、坐标、输入和来源映射的程序检查；识别文本明确标注，不能冒充原生正文。

详见：[向量化与存储设计方案](向量化与存储设计方案.md)。

## 三、检索方案

采用“BM25＋向量召回 → RRF 融合 → 回取父块及必要关联 → 生成带引用回答”。保留原来的双路召回与上下文恢复，去掉独立重排模型、自动任务拆解、循环补取和复杂的跨来源去重编排。

原生文本沿用现有RAG chunk_id，区分完整块范围和实际返回范围。跳过元数据及正文前空白，正文首字符为0，之后保留全部字符；采用0起点、左闭右开、Unicode码点，offset_basis=body_first_non_whitespace，以body_origin反算原文件。媒体使用source_id，OCR单独采用父转录串坐标，原图用像素框；不把OCR当Markdown原句。真实适配器、启动预加载一次、单进程共享、正文/OCR分页及原图/区域data URL回取均已实现，内部ID、原文和索引不变。

原文引句与出处的目标是由程序按来源版本和位置生成并核对。当前 Agent 主要验证已登记 ID，尚未逐字核对 quotes；不能把目标设计称为现有保证。新增证据类型需记录完整块范围、已见范围、版本和真实章节，历史引用保留旧对象/快照。回答仍须保留对象、条件和例外；位置正确不等于结论一定成立。

详见：[检索设计方案](检索设计方案.md)。
