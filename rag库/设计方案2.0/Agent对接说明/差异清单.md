# Agent V0.1 与 RAG proposal-v0.3 的差异清单

日期：2026-10-23。对照依据：[kb_contract.md](../../../agent/contracts/kb_contract.md)、Agent当前代码、本地RAG当前代码及[接口适配说明](接口适配说明.md)。本清单用于划分后续修改，不代表代码已经修复；本轮只完善对接材料。

## 1. 双方各自负责什么

- RAG侧：实现同步适配器、过滤映射、原文定位和正文坐标转换、章节目录、按块/章节分页、启动加载与索引共享。
- Agent侧：扩展Protocol、数据类型、工具入参和参数透传，接入真实后端配置，登记完整范围与已见范围，核对引用原句。
- 双方共同：使用proposal-v0.3样例作为契约依据，约定错误状态和版本定位，联调后再报告生产接入完成。

## 2. 逐项差异与修改位置

下表“待改”均为后续实施事项，当前未修改Agent或RAG工程代码。

| 项目 | 当前差异 | 目标行为 | 责任与修改位置 |
|---|---|---|---|
| 真实后端入口 | Agent只有MockKB；RAG只有query返回嵌套dict | 实现name及同步search/read，返回目标类型对象 | RAG新增适配器；Agent [kb.py](../../../agent/src/guance_agent/kb.py)接入后端 |
| 后端配置 | Settings拒绝非mock值 | 增加真实后端配置及路径/生命周期注入，保留mock供测试 | Agent [config.py](../../../agent/src/guance_agent/config.py)、[orchestrator.py](../../../agent/src/guance_agent/orchestrator.py)及进程启动入口 |
| 启动与共享 | query每次开关库；Mock首次使用才缓存 | 启动时加载一次、固定发布和目录，多请求通过队列共享，退出统一关闭 | RAG运行时＋Agent启动装配；不能在每个run重新建库实例 |
| 线程/锁 | Agent to_thread线程不固定，现有SQLite连接有限制 | 一个库线程拥有连接与索引，保留项目锁/Qdrant锁 | RAG运行时；不以关闭线程检查或删除锁代替生命周期管理 |
| 地区/时期过滤 | Agent area包含匹配；RAG多为等值过滤、字段名不同 | area映射area_name允许集合，fyp归一化后对应period_key；两路在同一允许集合内取Top-K | RAG适配器/查询；保留Agent normalize_fyp，不猜行政区划或规划期 |
| 来源合并 | query先按representation融合，最后按source去重 | 每路同source先取最好名次，再做RRF；各文档出处独立 | RAG [operations.py](../../向量化与存储工程（降级版）/vector_store/operations.py)及检索实现 |
| 完整块与预览 | Hit只有实际content的char_start/end，无法区分完整范围 | 增加chunk_char_start/end、truncated；char_start/end只代表本次content | RAG构造字段；Agent [schemas.py](../../../agent/src/guance_agent/schemas.py)扩展Hit |
| 对外坐标 | RAG内部按完整MD；旧契约body没有约定新原点 | 正文首字符0起点、左闭右开、Unicode码点，增加offset_basis/body_origin；内部数据不迁移 | RAG按版本换算；Agent使用返回值，不二次减原点 |
| ID与版本 | 当前证据类型主要记录planid和chunk_id，缺版本及坐标基准 | 沿用RAG chunk_id；保留document_id、document_version_id、source_hash、generation_id及原点 | 双方扩展类型与EvidenceRef；不以representation_id替换来源ID |
| 章节身份 | 只有section_idx/path；RAG没有已发布idx目录 | 返回真实section_id；按版本冻结idx目录；section_path沿用原父块 | RAG目录投影；Agent类型及契约保存版本定位 |
| 按块读取 | kb_read没有chunk_id；整章从头返回 | 增加chunk_id，按主键定位原文件和范围，返回所属章节；检查planid及章节归属 | RAG read；Agent [kb.py](../../../agent/src/guance_agent/kb.py)、[tools.py](../../../agent/src/guance_agent/tools.py) |
| 超长续读 | 没有offset，截断后无法继续 | 增加offset、next_offset、read_scope；块或章节内分页，拼接还原完整原文 | RAG分页；Agent工具暴露参数、模型按next_offset继续读 |
| 关键字参数透传 | _call只接*args，read校验只处理旧三个位置参数 | 保留后端前三个位置参数，新增定位参数以关键字传入，并联动验证 | Agent tools.py；只改kb_read签名不够 |
| 页内ChunkSpan | 只列整块完全包含的片段 | 保存完整范围、本页交集及complete，部分块不能登记为已读完整块 | RAG页投影；Agent schemas.py与[context.py](../../../agent/src/guance_agent/context.py) |
| Passage范围语义 | 未明确目录/章节/块三种响应 | 按read_scope处理；章读不伪造单个chunk，目录不登记正文证据 | 双方类型、工具和证据登记 |
| 证据登记 | 后读覆盖前读，仅planid冲突会拒绝 | 按chunk及版本合并observed_ranges，保留完整块范围和正文原点，检测真实版本冲突 | Agent context.py |
| 引句核验 | output只过滤已登记ID，quotes尚未逐字比对 | 引句必须来自本次已提供范围，换回同版快照逐字核对；不将位置校验称为语义保证 | Agent [output.py](../../../agent/src/guance_agent/output.py)＋RAG原文回取 |
| 错误包装 | RAG内部ValueError/None等未映射业务异常；KBNotFound信息不含chunk | 分开invalid_argument、not_found、no_text、timeout、backend_error；块不存在不误写成章节不存在 | RAG适配器异常；Agent kb.py、tools.py与ToolResult |
| 图片/OCR | 现有类型只表达原生文本位置 | 首轮显式限定text_chunk；媒体以后使用独立来源和坐标类型 | RAG过滤；双方后续扩展，不能伪造MD坐标 |
| 原文入口 | 现有snapshot为本地相对路径，没有原文HTTP服务 | 保存真实快照及范围定位；需要远端展示时再实现受控访问 | RAG定位信息＋后续展示层，不生成虚构URL |
| 文档与样例 | 旧契约V0.1，当前设计/JSON为proposal-v0.3；旧导出脚本仍产V0.2 | 联调时更新契约、类型、工具、样例和README，升级导出脚本后才能再生成新样例 | 双方；本轮不改旧脚本、核查报告或Agent现行契约 |

## 3. 为什么不能只增加几个JSON字段

[现有类型](../../../agent/src/guance_agent/schemas.py)会忽略未声明字段。即使底层返回chunk_char_start/end、section_id、body_origin、next_offset，旧Hit/Passage/EvidenceRef仍会丢掉它们；ToolResult数据类型和context登记也要联动修改。现行[kb_contract.md](../../../agent/contracts/kb_contract.md)中“仅加get_kb分支即可接入”的说法，不足以覆盖本次接入范围。

`_call`当前在后端执行前只验证旧参数。新参数校验、异常映射和参数透传必须一并设计，否则会把调用错误当成后端故障，或让新增参数根本传不到read。

## 4. 现有证据与样例能证明什么

- [Hit](samples/Hit.json)和[Passage](samples/Passage.json)来自同一真实块，带完整元数据、原始ID、版本和正文坐标；完整块451码点，预览300码点。
- [章节Passage](samples/章节Passage.json)包含6000码点的章节正文、10个块交集及截断状态；[长块两页](samples/长块第1页.json)与[续页](samples/长块第2页.json)覆盖同一6134码点块。
- 新样例标记proposal-v0.3，正文原点为254或253；文本、ID不变，按冻结快照逐字可还原。
- [历史核查报告](核查结果.json)记录原始范围/ID、原文哈希、主键查询计划及旧样例验证；它保持文件坐标，不是生产接口验收报告。
- 尚无生产适配器运行证据、启动加载次数/并发验收或真实模型问答评测；本材料不把这些状态写成完成。

## 5. 后续最小验收项

| 验收行为 | 应观察到的结果 |
|---|---|
| 启动后连续查询及多请求进入 | 索引只加载一次，同一运行时共享，run结果和证据不串用 |
| 以Hit中的chunk_id回读 | 对应planid、同版本原文、相同完整块范围及真实章节 |
| 对6134码点块读取offset=0、6000 | 返回6000＋134码点，页边界相接，拼接与完整原文一致 |
| 章节分页包含半个块 | 该块complete=false，只登记实际提供的交集 |
| 坐标含开头空白、内部空白、CRLF和非BMP字符 | 对外正文范围及反算文件范围逐字一致，正文内部不清洗 |
| 错误planid、未知chunk、负offset、版本冲突 | 分别按契约拒绝，不返回错误来源或空成功 |
| 多次读取同一块 | 已见范围合并，未读部分的引句不获批准 |
| 使用旧引用或重建索引 | 旧来源保留并按原版本回看；复用冻结切块产物时不重编号 |

这些是后续工程验收要求，本轮只交付对接材料，不执行生产接入或变更数据库。
