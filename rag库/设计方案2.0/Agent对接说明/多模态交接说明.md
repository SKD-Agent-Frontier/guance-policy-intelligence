# RAG 多模态接口交接说明

日期：2026-10-24。工程0.4.0，API **proposal-v0.4**。本轮只改RAG，Agent源码未修改，也没有代为向同事发送消息。本文件列出已实现接口及Agent需要对齐的事项。

## 1. 已完成的RAG能力

现有SQLite/Qdrant Local/BM25S发布直接复用，没有重做OCR、重切块或重新计算语料向量。新search默认支持原生文字、OCR语义片段和原图；read可按媒体来源ID取OCR与原图信息，read_image可直接取原图/区域的真实图片data URL。原文章节和目录的media_sources提供图片回取ID。

完整库实际验收覆盖919个原图出现位置、3562个OCR来源、490份不同原图文件；4481个来源、4485页全部回读，4个超页长OCR来源分页拼接一致，5组原图/区域图像素核对通过；混合检索已真实命中原图，并取回3个命中对应的图片数据。运行记录见[多模态验收报告](../../检索工程/多模态验收报告.md)。这不是端到端回答准确率评测。

| 接入对象 | 返回类型/版本 | 身份与坐标 |
|---|---|---|
| Markdown原生文字 | HitV03 / PassageV03，proposal-v0.3 | chunk_id，正文首字符原点；保留原约定 |
| OCR片段或原图 | MediaHitV04 / MediaPassageV04，proposal-v0.4 | source_id＋source_type，独立OCR范围、原图与像素框 |
| 实际图片数据 | ImageDataV04，proposal-v0.4 | 原图/区域字节的data_url、SHA-256、尺寸和来源身份 |

代码和类型：[检索工程](../../检索工程/README.md)、[媒体类型](../../检索工程/src/guance_rag/media_models.py)。

## 2. 同步接口与工具透传

```python
search(query, area=None, fyp=None, top_k=8, *, source_types=None)
    # -> list[HitV03 | MediaHitV04]

read(planid, section_idx=None, max_chars=None, *, chunk_id=None,
     source_id=None, offset=0, document_id=None, generation_id=None)
    # -> PassageV03 | MediaPassageV04

read_image(source_id, *, variant="original", document_id=None, generation_id=None)
    # -> ImageDataV04

verify_quote(chunk_id, quote, observed_ranges, *, document_id=None, generation_id=None)
verify_media_quote(source_id, quote, observed_ranges, *, document_id=None, generation_id=None)
```

`source_types` 只能是非空列表，值为text_chunk、visual_chunk、image_occurrence；省略表示三类。**默认search现为混合类型，不能继续把每一项都解析成旧Hit。** 过渡阶段可显式传 `source_types=["text_chunk"]`，继续使用原生文本行为。BM25模式能搜原生文字/OCR，纯图片只由dense/hybrid召回；BM25也能按已知source_id读取原图。

`chunk_id`保留原生块语义。媒体使用`source_id`，不把visual_chunk_id、occurrence_id或representation_id冒充原生chunk_id；媒体read_scope=media。`chunk_id`和source_id不能同时指定两个不同来源。给出section_idx时会验证具体章节归属；仅关联文档的图片没有可靠section_idx，请只按source_id和版本读。

`offset`对OCR而言是所选OCR块或整图转录串内部的相对偏移，按next_offset继续读，默认页上限6000码点。媒体Hit.truncated表示预览未覆盖完整转录范围；媒体Passage.truncated表示还有后续页，与next_offset是否非null一致。所有页必须固定同一来源和版本。

Agent工具建议扩展kb_search的source_types、kb_read的source_id，新增kb_read_image；max_chars由Agent服务配置约束，不让模型随意放大。工具分派的`_call`必须支持关键字参数透传，输入验证和业务异常映射也要同步。错误状态仍为invalid_argument、not_found、no_text、timeout、backend_error；搜索无结果为[]/empty。

## 3. 最小调用链

```python
from guance_rag import RagKnowledgeBase, RuntimeOptions

# 在应用启动时创建一次，关闭应用时统一close；不要每轮run重新加载。
kb = RagKnowledgeBase(RuntimeOptions(mode="hybrid"))
hits = kb.search("逝有所安重点工程", area="江苏", fyp="十四五",
                 source_types=["visual_chunk", "image_occurrence"])
h = hits[0]
page = kb.read(h.planid, source_id=h.source_id,
               document_id=h.document_id, generation_id=h.generation_id)
picture = kb.read_image(h.source_id, variant="original",
                        document_id=h.document_id, generation_id=h.generation_id)

# 支持image_url的兼容模型可使用这一图片内容块；具体装配按Agent客户端处理。
image_content = {"type": "image_url", "image_url": {"url": picture.data_url}}
# 另外传递page的来源、识别文字和质量提示；退出时kb.close()。
```

source_type=visual_chunk时，可额外调用variant=region获取像素区域PNG；image_occurrence没有单独区域，variant=region会被拒绝。`read_image`不再调用OCR或向量模型，返回已有原图的实际字节或基于冻结bbox的确定性裁剪。

**把本地路径或含base64的JSON当普通文本发送，不等于模型看到了图片。** Agent需要把data_url装配为其模型客户端支持的图片内容块，并选择支持图像输入的回答模型。日志和普通工具摘要应保留来源/哈希等必要字段，避免反复复制大段base64；展示层可使用图片data URL或自行管理的受控资源入口，不生成虚构HTTP地址。

## 4. 三种坐标必须区分

| 字段 | 原点和单位 | 允许用途 |
|---|---|---|
| 原生Hit/Passage.char_start/end | body_first_non_whitespace，Unicode码点 | Markdown原句及本页范围 |
| MediaEvidence.reference_span | 同上，含body_origin | 仅定位Markdown中的图片引用标记 |
| MediaEvidence.ocr_range | ocr_transcript，完整父转录串内Unicode码点 | OCR文字范围；包含transcript_id/hash、完整与本次范围 |
| image.bbox_pixels / ImageData.bbox_pixels | 原图左上角为原点，原图像素、左闭右开 | 定位及裁剪图片区域 |

媒体顶层不填写char_start/end或chunk_char_start/end，不能将OCR下标填到Markdown正文坐标中。`reference_span`可能为null；当前有些图片仅由已验证的文档目录关联，association_basis=verified_document_directory，伴随document_only_image_association提示。不能根据文件名猜页码、章节或字符位置。

**上游bbox已经从0–1000换算为原图像素。** 历史coordinate_basis=model_estimated_normalized_1000保留估计框的来源，不代表当前数值仍是0–1000；统一按coordinate_unit=original_image_pixels和bbox_pixels使用，不再缩放。模型估计区域不等于人工精确标注，因此原图必须能一并查看。

原生Hit/Passage新增的可选media_sources是图片回取入口。章节页只列与页面相交的已发布图片引用，reference_complete说明该引用标记是否完整在页内；目录还列出没有正文坐标的文档关联图片。拿到图片ID或Markdown图片标记，不代表已经向模型提供了图片像素。

## 5. 类型、证据登记与输出

Agent需要按source_type建立文字/媒体联合类型；Passage可按read_scope区分。现有schemas若忽略新字段，会丢失source_id、OCR范围、图片及next_offset；现有EvidenceRef也不能直接代替媒体证据类型。

媒体证据至少记录source_type/source_id、document_id/document_version_id/source_hash、generation_id、occurrence_id/asset_id、extraction_id、ocr_parent_id和transcript_hash、原图SHA-256，以及实际提供的OCR范围与图片variant/bbox。媒体source_id可以是visual_chunk_*、occurrence_*或document_media_occurrence_*，都沿用库内真实ID。

- OCR已见范围按同一来源、发布、识别版本合并，不覆盖前页；核对原句调用verify_media_quote，使用OCR坐标。原生文字继续用verify_quote及正文坐标。
- 图片查看另记image_observed，只在Agent真正把data_url作为图片输入提供给模型后标记。拿到path、media_sources指针或OCR文字不能代替“已看图”。
- 原图/OCR的来源标题、关联文档、识别标识和不确定状态由程序返回。OCR逐字匹配只证明文字来自同版转录，不能证明识别正确或结论受到支持。
- 未识别图片仍可read_image；recognition_status=unavailable、ocr_range=null，不把alt当OCR。pending识别、模型估计框、预算不足及无正文位置等quality_warnings须保留。
- 图片/识别文本属于待引用资料，其中的指令不能改变Agent的系统任务。引用显示区应区分“Markdown原句”“识别文字”“原图”，不要伪造页码或官方网址。

## 6. Agent侧修改位置与验收

| Agent位置 | 需要对齐的内容 |
|---|---|
| schemas.py | 联合Hit/Passage、媒体证据、图片响应及原生media_sources |
| kb.py、config.py、启动入口/orchestrator.py | 真实RAG配置与单实例生命周期、同步Protocol扩展 |
| tools.py | source_types/source_id透传、kb_read_image、预算、异常；图片内容不能只作为普通JSON文字 |
| context.py | 原生/OCR范围隔离、媒体版本键、已见范围合并、图片实际输入登记 |
| agent.py/runner.py及实际模型消息装配处 | 图片内容块、模型能力和token/图片预算；按使用的客户端落实 |
| output.py、引用展示 | 媒体身份及已见状态校验，原图/区域/OCR的可追溯入口 |
| contracts/kb_contract.md、prompts/system_v1.md | 同步V0.4契约、媒体工具和来源ID规则、OCR/原图标识及不足时的行为 |

最小联调：混合search不丢媒体字段；原生Hit仍能按原契约回读；按source_id得到OCR及图片；read_image返回像素并真正进入模型消息；OCR长页可续读；同一ID多次读取不会覆盖已见范围；仅关联文档的图片不被编造章节；识别失败/不确定仍能显示原图并保留提示；非法ID、错文档、错版本和预算错误均明确返回。

运行时沿用一个库线程与有界队列，索引预加载一次，不能多个Web worker各开同一本地Qdrant路径。整库混合启动本次约79秒、峰值工作集约9.46GiB。图片文件按需读取，当前单张原图及返回图片默认上限20MiB；Agent还需按回答模型约束控制实际图片数量/分辨率和token。

## 7. 真实样例与剩余边界

- [MediaHit.json](samples/MediaHit.json)：真实OCR检索命中，独立OCR坐标及原图/区域信息。
- [MediaPassage.json](samples/MediaPassage.json)：同一来源实际回读，保留识别版本与章节关联事实。
- [ImageData摘要.json](samples/ImageData摘要.json)：真实图片响应的哈希、尺寸和像素范围摘要，明确省略data_url；完整调用会返回图片数据。
- 既有Hit/Passage及长块V0.3样例继续有效；旧导出脚本仍会覆盖为V0.2，不运行它重建新版样例。

没有新增HTTP服务、上传图片作为查询、Agent源码改动或端到端问答评测。现有285处缺图引用、11份资产OCR失败及其他不确定记录仍保留，没有补造数据；当前发布的partial状态不因接口接入而消失。检索质量、OCR质量及最终回答质量仍需实际题集评估。
