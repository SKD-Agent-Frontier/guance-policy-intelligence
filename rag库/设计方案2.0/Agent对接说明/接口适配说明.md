# Agent 与 RAG 接口适配说明

更新日期：2026-10-24。契约版本：`proposal-v0.3`。接入对象：本地 SQLite＋Qdrant Local＋BM25S。[独立RAG工程](../../检索工程/README.md)已实现 `RagKnowledgeBase`、`HitV03/PassageV03`、常驻共享和分页，并通过[真实库验收](../../检索工程/验收报告.md)。Agent源码未修改，由同事按本文接入。

## 1. 接口形式与接入位置

采用**同步 RAG 接口＋Agent 异步调用＋进程内共享运行时**，本阶段不提供独立 HTTP 服务。RAG 适配器满足下列目标 Protocol；`HitV03`、`PassageV03`是本文约定的目标类型名，当前 Agent 尚未定义它们。

```python
class KnowledgeBase(Protocol):
    name: str

    def search(self, query: str, area: str | None,
               fyp: str | None, top_k: int) -> list[HitV03]: ...

    def read(self, planid: str, section_idx: int | None, max_chars: int, *,
             chunk_id: str | None = None, offset: int = 0,
             document_id: str | None = None,
             generation_id: str | None = None) -> PassageV03: ...
```

Agent 模型可见的读取参数为 `kb_read(planid, section_idx=None, chunk_id=None, offset=0, document_id=None, generation_id=None)`，返回仍为 ToolResult JSON。`max_chars`由服务配置传给同步后端，默认6000，不由模型任意放大。

| 当前代码 | 对接时要做的事 |
|---|---|
| 独立RAG `RagKnowledgeBase` 已返回扩展类型 | Agent安装/导入检索包，复用启动实例，扩展其类型并映射业务异常 |
| Agent `get_kb()`只创建MockKB，配置也只接受mock | Agent增加真实后端配置，启动时构建并注入适配器 |
| Agent工具通过`asyncio.to_thread`调用同步KB | 保留异步等待；适配器把库任务交给固定工作线程，不跨线程直接使用现有SQLite连接 |

代码依据：[Agent KB](../../../agent/src/guance_agent/kb.py)、[配置](../../../agent/src/guance_agent/config.py)、[工具](../../../agent/src/guance_agent/tools.py)、[RAG query](../../向量化与存储工程（降级版）/vector_store/operations.py)。仅加`get_kb()`分支还不能完成接入，类型、配置、参数透传和证据登记需一起修改。

## 2. search参数与返回规则

| Agent参数 | RAG目标映射与校验 |
|---|---|
| query | 对应text；去除查询首尾空白后为1–200字符，不修改证据原文 |
| area | 对应真实元数据area_name；允许包含匹配，空白视为未指定，最长50字符。先确定允许来源集合，再在两路Top-K前过滤；不能猜行政区划或召回后才过滤 |
| fyp | Agent先沿用normalize_fyp，RAG映射period_key/fyp_name；最长50字符，精确匹配，未知值不猜成年份或规划期 |
| top_k | 对应limit；模型工具默认8，上限20；后端接收实际传入值 |

第一阶段显式限定`source_type=text_chunk`，不把图片/OCR坐标混入原生文本类型。元数据缺失保留null，不满足已指定的硬过滤条件；无命中返回`[]`，由工具包装为empty。

独立检索工程采用BM25＋dense、RRF及原有父块/必要关联回取，已实现每路同一source先取最佳原始名次，再融合并返回独立来源。旧query保持原实现；新Agent接入使用RagKnowledgeBase。score是排序值，不是正确率或政策支持概率。

`Hit.content`是最多300码点的连续原文预览；完整块范围不受预览预算影响。预览可以位于块中间，不要求char_start等于chunk_char_start，但必须完整落在该块范围内。标题增强前缀、模型说明和其他条件不得拼进content。

## 3. read定位、原文回取与续读

### 3.1 输入选择

| 输入 | 目标行为 |
|---|---|
| 不给section_idx和chunk_id | 返回选定版本的章节目录，is_index=true、read_scope=index，content为空、正文范围为null；offset必须为0 |
| 仅section_idx | 从指定章节相对offset读取一页，read_scope=section，返回真实章节身份及完整章节范围 |
| 仅chunk_id | 直接定位原子块，从块内offset读取一页，read_scope=chunk，返回完整块范围及所属章节，不从章首重读 |
| 两者都给 | 先校验块属于该版本目录中的指定章节；冲突返回invalid_argument |
| document_id/generation_id | 给出时必须与所选来源及发布成员关系一致；无chunk时默认当前冻结发布对应文档，给chunk时以其绑定版本定位，历史来源缺失明确not_found |

section_idx是固定版本目录内的便利编号，不是全库章节ID；目录按`(start,level,id)`排序，root=0。其定位范围为`(generation_id, document_id, section_idx)`。不能用新版目录解释旧章节编号。

### 3.2 原文不是全文搜索得来的

```text
chunk_id → SQLite objects.id主键 → document_id、原文件范围、parent_id
         → documents.id主键 → 对应版本snapshot、source_hash
         → 打开或复用该篇冻结Markdown → 按范围取完整原文
         → 原父块structure_id → 真实section_id和section_path
```

[现有object()](../../向量化与存储工程（降级版）/vector_store/sqlite_metadata.py)已经支持主键回取，数据库中保留完整source_segments。无需扫描全部切片或搜索匹配句子；未缓存时仍需读取并严格解码目标文档。若只拿`chunks.jsonl`而不使用数据库或预建映射，查ID需要扫描该文件。

chunk_id校验对象类型及planid归属已实现。正式`read(chunk_id=..., offset=...)`受分页预算约束；程序便捷方法`get_chunk_source(chunk_id)`返回完整原文及章节，不应直接无预算塞给模型。

### 3.3 超过6000字必须能续读

当前数据有41个原生块超过6000码点，最长91631。仅加chunk_id不能保证一次响应装下完整块。

- offset为所选块或章节内的码点偏移，默认0；必须为非负整数。非空对象的offset必须小于其长度，不能返回含糊的空成功页。
- 每页最多max_chars码点。未读完时truncated=true，next_offset指向同一对象的下一页；读完时truncated=false、next_offset=null。
- offset/next_offset不减body_origin；它们是对象内偏移，char_start/end则是正文坐标。
- `Passage.chunks`列出与本页有交集的块，同时保存完整块范围和可见交集；complete只表示该块是否整块出现在本页，不能把部分块登记为已完整读取。
- 每次续读继续使用同一chunk/章节及版本参数；拼接各页须逐字还原原文。服务保留完整数据，不把未返回部分丢弃。

## 4. 字段契约与来源映射

### 4.1 Hit和Passage共有的来源信息

| 字段 | 来源、语义与处理 |
|---|---|
| planid、title | 文档原始编号与标题，不由Agent补造 |
| area、fyp、admin_level、plantype_label | 原文元数据area_name、fyp_name、admin_level、plantype_label；缺失保留null，空字符串转null |
| document_id | 原切块文档ID，绑定planid和source_hash，用于查documents主键 |
| document_version_id | 向量工程的版本标识；不是document_id的替代主键 |
| generation_id | 来源所属冻结发布；不得一次请求混用两版数据 |
| source_hash、snapshot、source_path | 原字节SHA-256、冻结快照相对路径、原始语料相对路径；不是已部署HTTP网址 |
| contract_version | 固定为proposal-v0.3；不能仅换版本号而不换算范围 |
| offset_basis、offset_unit | 固定为body_first_non_whitespace、unicode_codepoint |
| body_origin | 正文原点在完整文件中的绝对码点位置，用于确定性反算 |
| body_start | 既有元数据结束位置，属于原文件坐标；不能当成body_origin |
| section_id、section_idx、section_path | 真正结构ID、版本目录内编号、真实标题路径；原路径数组用` / `连接，空路径保持空字符串 |
| contexts、required_relation_ids、quality_warnings | 必要原文上下文、已记录关联、原有质量提示；不把pending块自动当成不存在，也不将提示当作证据已充分 |

非空contexts中的文本片段保留各自文档/版本、原点、原文范围与文字；不同来源各自换算。检索增强输入retrieval_text不作为原文content。

### 4.2 Hit专有字段

| 字段 | 语义 |
|---|---|
| chunk_id | `source.id = record.source_id`，即原始块证据ID；不换成Agent自编编号、point_id或representation_id |
| parent_id | 原父块ID，保留主块原始章节归属 |
| chunk_char_start / chunk_char_end | 完整块在正文中的固定范围 |
| content、char_start / char_end | 本次连续预览及其正文范围，必须逐字一致 |
| truncated | 本次content是否未覆盖完整块 |
| score | 本次检索排序分值，不当概率解释 |
| source_type、representation_id | 本轮为text_chunk；表示ID仅供追溯，不能代替chunk_id引用 |

### 4.3 Passage专有字段

| 字段 | 语义 |
|---|---|
| read_scope、is_index | index/section/chunk；只有目录响应is_index=true |
| chunk_id、parent_id、chunk_char_start/end | 按块读时必有；按章/目录读可省略或为null，不能将整章假称一个chunk |
| section_char_start / section_char_end | 所属章节完整正文范围；目录响应可为null |
| content、char_start / char_end | 本页原文及实际正文范围；目录响应content为空、范围为null |
| truncated、next_offset | 是否还有后续页，以及对象内的下一页起点；读完时next_offset=null |
| chunks | 每项为chunk_id、完整块chunk_char_start/end、本页交集char_start/end、complete |
| sections | 目录响应列idx、section_id、path、char_start/end和chars；普通正文响应为null |

## 5. 原文坐标、ID和章节约束

跳过头部元数据及正文前面的空白，正文首字符记为0；之后所有空格、换行、Markdown符号均保留并计数。采用0起点、左闭右开、Unicode码点，不是UTF-8字节或浏览器UTF-16下标。

body_origin从body_start起，仅向后跳过满足Python str.isspace()的开头字符；没有元数据时先跳过文件首BOM（若有）。正文全为空白时按无正文处理；Markdown首个`#`也算正文字符。CRLF保留原样，不做通用换行转换。

```python
body = source_text[body_origin:]
assert content == body[char_start:char_end]
assert full_chunk == body[chunk_char_start:chunk_char_end]
assert content == source_text[body_origin + char_start:body_origin + char_end]
# 以下包含关系针对按块返回的主content，不适用于其他来源的contexts。
assert chunk_char_start <= char_start <= char_end <= chunk_char_end
```

章节、页内块和原生文本上下文范围也采用同一规则。数据库、原始source_segments及ID生成输入仍保留文件绝对坐标，转换只发生在接口边界，不迁移数据库或重新切块。正文原点前的异常块不能静默截成0；根目录对外范围从正文0开始。

原chunk_id形如`chunk_<32位摘要>`，绑定文档版本、原父块、原始范围和切块配置；复用同一冻结产物重建存储时保留原ID，重新切块不承诺无条件稳定。历史引用必须保留版本、offset_basis/body_origin及已见范围。

章节沿用原父块structure_id。当前42516个原生块的核查未发现跨越已识别章节边界；不等于所有标题都已人工确认。共同条件和其他章节内容单独放contexts/relations，不改变主块section_path。未来真有跨章块时明确多章节或调整切分，不能随意取一个路径。

## 6. 工具包装与错误状态

同步后端返回目标类型对象，Agent工具继续包装`{status, message, data}`。旧Pydantic类型会丢弃新增字段，必须联动扩展Hit、Passage、ChunkSpan、EvidenceRef和ToolResult，再做证据登记。

| 情况 | 后端/工具约定 |
|---|---|
| 没有检索命中 | 后端返回[]，工具返回empty |
| 未知文档、块、章节或版本已缺失 | 映射KBNotFound，工具返回not_found；错误信息能指明chunk，不能一律写成章节不存在 |
| 已知文档确无正文 | 映射KBNoText，工具返回no_text |
| 参数类型/范围错误、planid归属错误或块与章节冲突 | 工具返回invalid_argument；用户参数校验不得被误包装成backend_error |
| 排队或执行超过限制 | timeout；等待超时不等于后台线程任务已终止 |
| 快照哈希/坐标损坏、索引或后端故障 | backend_error；不伪装empty或no_text，不对外泄露凭证和内部异常详情 |

当前`_call`只传位置参数，read校验也只有旧三项。新增关键字参数必须显式透传并联动校验，不能只修改工具函数签名。EvidenceRegistry需合并同块同版本的observed_ranges，不能覆盖前页；引句只批准来自本次实际提供范围的原句，存在chunk_id不等于整块已读或结论得到支持。

## 7. 启动加载与请求共享

一个专用库线程负责SQLite/Qdrant/BM25的打开、查询和关闭。启动时固定发布，建立只读SQLite查询连接，加载成员、冻结章节目录、BM25及所需dense集合，按文档版本缓存body_origin；完成后才ready。同步search/read通过有界队列提交给该线程，首版库操作串行，多请求共享索引，run的结果和证据各自隔离。

不把现有SQLite连接交给任意to_thread线程；保留项目锁和Qdrant路径锁，不启动多个worker打开同一Local目录，不删除锁绕过限制。业务不修改语料、索引成员和发布；SDK锁/WAL维护与独立问题缓存不等于整个文件系统零写入。关闭时停止接收并处理退出，更新采用受控关闭/重新加载，排队和执行分别设限。完整库启动与12个并发调用验收已通过，BM25/dense加载次数各为1。混合启动约83秒、峰值工作集9.486GiB；操作在库线程中串行执行，尚无吞吐量承诺。

## 8. 两条真实样例与回读关系

完整机器样例：[Hit.json](samples/Hit.json)、[Passage.json](samples/Passage.json)。二者来自planid=20699《苏州市“十四五”民政事业发展规划》，此前BM25查询“养老服务”第1名，属于真实数据投影，未重新调用检索或模型。

| 检查项 | 真实值 |
|---|---|
| chunk_id | chunk_c5481643e7c67d653e29160c30719104，两条样例相同 |
| section_id / section_idx | section_aa3464a90b5898f38ba5c38fa030ce26 / 4；idx为目录提案值 |
| body_start / body_origin | 253 / 254，正文前还有1个开头空白码点 |
| 完整块正文范围 | [10864,11315)，451码点；内部文件范围为[11118,11569) |
| Hit实际可见范围 | [10864,11164)，300码点，truncated=true |
| Passage实际范围 | [10864,11315)，451码点，truncated=false、next_offset=null、chunks[0].complete=true |
| 所属章节 | 第四部分主要任务，正文范围[8286,19608) |

读取这条Hit时，目标工具参数为`planid="20699", chunk_id="chunk_c5481643e7c67d653e29160c30719104", offset=0`，应返回上述完整块及所属章节，而非从章首返回6000字。若要验证章节正文，看[章节Passage.json](samples/章节Passage.json)：6000码点、10个页内块交集，truncated=true。

长块示例：[第1页](samples/长块第1页.json)、[第2页](samples/长块第2页.json)。planid=48787，chunk_id=chunk_594a17c56902e7fdac2a38662282ebda，完整6134码点；首读offset=0得到6000码点和next_offset=6000，续读同块offset=6000得到134码点和next_offset=null。两页连续、拼接逐字等于完整原文。
