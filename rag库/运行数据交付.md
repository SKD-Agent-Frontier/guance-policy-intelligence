## 下载、校验和恢复

先克隆或更新本仓库，按[本地存储工程](向量化与存储工程（降级版）/README.md)安装锁定依赖；检索工程也需安装到同一Python环境。下面命令从仓库根目录执行，假设已建立`.venv-rag`环境。也可换成自己现有环境的Python。

```powershell
$ragPy = '.\.venv-rag\Scripts\python.exe'
& $ragPy -m pip install -r '.\rag库\向量化与存储工程（降级版）\requirements.lock.txt'
& $ragPy -m pip install -e '.\rag库\检索工程'

gh release download rag-v0.4.0-data-20261024-r1 `
  --repo SKD-Agent-Frontier/guance-policy-intelligence `
  --pattern '*.part*' --pattern 'delivery-manifest.json' --pattern 'SHA256SUMS.txt' `
  --dir 'D:\RAG下载'

& $ragPy '.\rag库\向量化与存储工程（降级版）\restore_delivery.py' `
  --manifest 'D:\RAG下载\delivery-manifest.json' --destination 'D:\RAG运行库'
```

也可在Release页面手动下载全部分卷和两个清单，放在同一文件夹。`D:\RAG运行库`必须尚不存在；恢复工具拒绝覆盖现有目录。工具先核对每卷大小和SHA-256，按清单顺序合并并核对整包SHA-256，再逐文件校验解压，拒绝路径越界，最后重定位SQLite和发布清单中的prepared/media路径。失败时不要使用不完整的目标目录；选择一个新的目录重试。需要同时容纳分卷、合并ZIP和解压结果，建议至少预留12GiB可用磁盘。

运行数据可以放在仓库之外；检索时显式指定其位置即可：

```powershell
& $ragPy '.\rag库\检索工程\run.py' --store-project 'D:\RAG运行库' --mode bm25 search '产业发展' --top-k 3
& $ragPy '.\rag库\检索工程\run.py' --store-project 'D:\RAG运行库' --mode bm25 serve
```

`serve`是标准输入输出JSONL接口。Python接入使用`RuntimeOptions(store_project=Path('D:/RAG运行库'), mode='bm25')`创建`RagKnowledgeBase`。同一服务进程共享一个实例，每次请求状态独立；同一路径的Qdrant Local不能由多个进程同时打开。后续多进程部署需要独立索引副本或切换服务端架构，并核算每进程索引内存。

## 混合／向量查询的本地配置

BM25、原文、OCR和原图回取不需要模型调用。新问题的dense/hybrid编码需要相同模型和向量空间；交付包以`__CONFIGURE_EMBEDDING_BASE_URL__`替代私有模型服务URL，凭证不随包发送。参考[配置模板](向量化与存储工程（降级版）/secrets.example.json)在本机建立配置文件，填写自己有权使用的服务地址和凭证，再关闭检索实例后执行：

```powershell
& $ragPy '.\rag库\向量化与存储工程（降级版）\restore_delivery.py' `
  --destination 'D:\RAG运行库' --configure-only --secrets 'D:\本地配置\secrets.local.json'
```

该步骤只向恢复目录复制本地配置并绑定发布清单的服务地址，不上传配置。原始profile_id、来源ID和输入哈希保留，私有URL占位符不是重算profile_id的输入。仅使用与原库一致的模型、tokenizer、模板和空间；新问题编码仍执行既有canary空间验证。不同服务返回的空间不一致时应重建新发布，不能通过改URL或关闭校验混用向量。OCR服务也需要接收方自己的配置，但读取已经交付的OCR结果无需重跑识别。
